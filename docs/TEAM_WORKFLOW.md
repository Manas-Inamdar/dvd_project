# TEAM_WORKFLOW

## 1. How we actually work
The assignment is carried out **interactively in Claude Code sessions between Manas and Claude**; the four teammates review and can take
over any task. Because Claude forgets between sessions, the repository documents are the memory.

### Start of every session (copy-paste this)
> Read CLAUDE.md, docs/PROJECT_CONTEXT.md, and docs/PROJECT_STATUS.md before proceeding. Continue from the last recorded project state.

### End of every session / after each milestone
1. Update `docs/PROJECT_STATUS.md` (done / in progress / blockers / tests / next steps).
2. Add any new decision to `docs/DECISIONS.md`; new ambiguity to `docs/PROJECT_CONTEXT.md` section 11.
3. Commit and push the branch.

## 2. Identity and privacy rules
* The Claude account in use belongs to a teammate; the person typing is Manas Inamdar. Commits are authored by the person who runs the session, with a `Co-Authored-By: Claude` trailer when Claude helped. (Repo-local git identity was set for Manas.)
* **Never commit**: WhatsApp screenshots, phone numbers, personal names from chats, credentials, absolute personal file paths, virtualenvs, raw SPICE logs.
* Any new chat/screenshot context must be transcribed and anonymized the same way as `context/whatsapp_messages.txt` before it touches the repo.
* The GitHub repo must be **private** while it contains course material.

## 3. Git workflow
* `main`: stable, always runnable. No direct pushes of experimental work.
* Branches: `initial-context`, then `feature/p1-spice-plumbing`, `feature/p2-datasets`, `feature/p3-ml-models`, `feature/p4-gates`, `feature/p5-circuit`, `feature/p6-report`; fixes `fix/<topic>`; docs `docs/<topic>`.
* Commits: small, imperative subject (<= 72 chars), body says what/why. Example: `Add NMOS ON single-transistor netlist builder`.
  Claude-assisted commits end with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.
* Merge to `main` through a pull request after: (a) tests pass, (b) `PROJECT_STATUS.md` updated, (c) one teammate has looked at the diff.
  Squash or merge commit - either, but never rewrite shared history (no force-push on shared branches).
* Before starting: `git fetch` and `git status`; never overwrite existing work without checking the diff.

## 5. Integration rules
* Shared interfaces (file formats) are fixed early: dataset CSV columns (assignment), `data/corners.csv`, `data/gate_spice.csv`, `models_saved/<case>.*` + `predict(case, features)` API.
* Config values live in `config/project.yaml`; change them there only.
* All random draws use seeds from the config. A result that cannot be regenerated by the scripts is not a result.
